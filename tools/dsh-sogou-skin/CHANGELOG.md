# 更新日志

本项目遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [0.2.0] — 2026-10-18

一次彻底的代码审查、重构与能力升级。仍保持**零第三方运行时依赖**（只用 Node 内置
`zlib` / `crypto`），工具名与 CLI 命令保持向后兼容（只增不减）。

### 重构
- 新增 `src/ops/` 应用层：工程 / 装配 / 打包 / 校验 / 预览 / 安装 / 修图 / 需求清单，
  **CLI 与 14 个工具共用同一份实现**。v0.1.0 里 `validate` 等操作在工具和 CLI 各写一遍，
  默认值、错误处理、检查项都不一致。
- CLI 命令表抽到 `src/commands.js`（帮助文本、README、测试共用同一真源）；
  `src/tools.js`、`src/cli.js` 退化为薄层。
- 新增 `src/util/`（CRC32 / 路径与文件 / 数字与文本工具），修掉 `image/png.js`
  反向依赖 `ssf/zip.js` 的层次倒挂。
- 九宫格模型收敛到 `src/skin/layout.js` 的 `computeLayout()` 单一真源：
  夹取、退化判定、平铺/拉伸、接缝、候选条背景都由它算，渲染器与校验器不再各说各话。
- 删除死代码与重复实现（`render.js`/`preview.js` 各自的 blit/棋盘格/缩放、
  未使用的导出、`tools.js` 里的业务逻辑）。

### 修复（Fixed）
- **v1 容器真正可读可写**：`"Skin"+u32(1)` 明文内层。v0.1.0 的 README/CHANGELOG 声称
  "三代全部可读写"，但 `readSkin()` 遇到 v1 直接抛错 —— 典型的"文档写了不存在的东西"。
  现在 v1 可 inspect / unpack / pack / validate，且本机 `skin_v3.dat` 实测
  "解包→重打包后与原文件逐字节相同"。
- **可选面板不再无条件生成**：`bar_mask`、三张分体底图只在工程显式分配时存在。
  修掉"每个工程都带一张占位 `bar_mask.png` 和假的 `[Scheme_H2]`/`[Scheme_V2]` 段落"的问题
  （真机上跑着的皮肤也带着这些假段落，等于给引擎换渲染路径）。
- **`anchors` 字段生效**：v0.1.0 的装配器根本没读工程里的 `anchors`（复刻工程声明了
  `Scheme_H1:[100,130]`，产物却写成 `50,17`）。现在显式 anchors 优先，没写才按
  `left/2,top/2` 推导（这组推导值在闲云 v1 真机上验证过）。
- **按钮坐标缺省不再重叠**：以前所有没写坐标的按钮都挤到 `[20,1]`。现在按状态栏底图宽度
  自动排布，排不下换行。
- **`left+right === 窗口宽` 不再被误判为九宫格退化**：这是合法设计（四角正好拼满、中段为 0，
  复刻-雷电将军的原生 400 宽窗口就是如此）。v0.1.0 的 `nineSlice()` 用 `>=` 判退化，
  会把整图压缩。
- **`layered` / `pic_mask` 默认不再写**：真实第三方皮肤都不用这些键，加了等于换渲染路径；
  只有工程显式开启（`layered` / `useBarMask`）才写。
- **`<按钮>_display=1` 默认写回**（v0.1.0 的行为是对的）：真机回归证明，去掉这 9 条
  `*_display` 后状态栏按钮在部分搜狗版本上**整体不显示**。可用 `buttons.writeDisplay: false` 关闭，
  校验器对缺失 `_display` 的产物会给提示。
- **校验器去误报**：对已知正常数据零 error 零 warning；启发式检查降级为 notes。
- **工程 schema 自校验**：类型错误变 `errors`（带字段路径），未知字段变 `warnings` 且
  **保存时原样保留**（不再静默丢作者数据）；`schema:1` 自动迁移到 2。
- **`roles` 支持字符串简写**（`"panel_h": "assets/a.png"`）；`assets.scale` 支持 2x 素材
  （装配时缩到逻辑像素，`Skin.ini` 数字仍按逻辑像素）。
- **装配器不再修改传入的工程对象**（v0.1.0 会往 `roles` 里塞 `generate:true` 并可能写回文件）。
- **图标默认格式从 BMP 改为 PNG**（BMP 是 24 位无 alpha，半透明会被合成到白底变成白方块）。
- 修掉旧测试里的**假通过**与**硬编码本机路径**（详见测试小节）。

### 校验器（Changed）
- 输出分三级：`errors` / `warnings` / `notes`。
  启发式检查（候选条背景覆盖率、中段色差、按钮坐标重叠）一律进 `notes`，并在文案里写明
  **已知反例**；只有真错误（结构缺失、引用悬空、九宫格退化、素材读不出来）才进 `errors`。
- 已知正常数据全部 **0 error、0 warning**：复刻-雷电将军工程、闲云 v1 工程、
  两套真实商店 `.ssf`、本机官方 `Skin.dat`。
- 新增检查：`layout_*`/`*_marge`/`anchor`/`pos` 元组格式、颜色 `0xBBGGRR` 合法性、
  Skin.ini 图片引用悬空、图标尺寸差异、九宫格在真实量级尺寸下的退化、
  可拉伸中段的稳定色差（接缝/花纹）、候选条背景覆盖率、体积上限。
- 支持三种输入：工程目录 / 已解包皮肤目录 / `.ssf` 文件。

## [0.1.0] — 2026-10-10

首个版本。

### 容器格式
- 识别并读写搜狗 `.ssf` 的**三代容器**：
  - **A 代**：普通 ZIP，条目带搜狗私有 `SD` 扩展字段（`53 44` / `0x4453`）
  - **B 代（v3）**：`"Skin" + u32(3)` + AES-256-CBC + zlib + 内部条目表
  - **C 代（v1）**：`"Skin" + u32(1)` + 明文内部条目表
- 手写 ZIP 读写器，逐字节对齐搜狗自己产出的包结构
  （条目数 / 名称 / **顺序** / 压缩方法 / version 字段 / 扩展字段长度）。
- `Skin.ini` 解析：UTF-16LE + BOM，CRLF/LF 兼容，
  **颜色是 `0xBBGGRR`（Windows COLORREF）而不是 RGB**。

### 图像层（零第三方依赖）
- PNG 编解码：8/16 位，灰度 / 调色板 / RGB / RGBA，Adam7 隔行。
- BMP 编解码：含搜狗特有的 20×20 按钮变体。
- 抗锯齿绘图原语：线 / 曲线 / 圆 / 圆角矩形 / 多段线性渐变 / 径向渐变 /
  外发光 / 内发光 / 高斯模糊 / 投影 / 颗粒 / **沿轮廓勾边**。
- 位图基元：缩放 / 裁剪 / 粘贴 / 九宫格 / 抠图 / 调色 / 主色提取 / 内容裁剪。
- 内置 5×7 点阵字体（用于预览图上的文字标注）。

### 皮肤层
- 键词表：304 个已知键、7 个段落、13 个按钮槽位、15 组官方浮层对齐预设。
- 九宫格探测与**退化体检**（`left+right > W` 会导致引擎整图缩放）。
- 装配器：从工程配置生成完整皮肤文件树 + `Skin.ini`。
- 程序化占位素材：不需要任何素材就能产出一套可用的皮肤。
- **引擎模型渲染器**：按标定出来的引擎行为真渲染，
  产出拟真预览图、拉伸体检图、**白底/黑底对照图**。

### 工具与接口
- 14 个 `skin_*` 工具（需求清单 / 建工程 / 扫描素材 / 分配 / 装配 /
  预览 / 修复 / 打包 / 解析 / 解包 / 校验 / 浮层预设 / 安装 / 列出已装）。
- 1 个技能 `sogou-skin-authoring`：把完整的创作流程写成可复用步骤。
- 独立 CLI：9 条命令，不装 DSH 也能用。

### 已标定的引擎行为
以下结论全部来自**真实皮肤与真机截图**，不是推测：

- **窗口尺寸**：宽度按内容算，**高度 = 底图原始高度，纵向永不缩放**。
  真机实测：底图 650×258 → 候选窗 460×259 逻辑像素（DPI 168）。
- **九宫格退化**：`left+right > W` 或 `top+bottom > H` 时引擎整图硬缩放。
- **候选窗是上下两排文字**：
  `拼音行 y = pinyin_marge[0]`、
  `候选行 y = pinyin_marge[0] + font_size + zhongwen_marge[0]`。
- **候选条必须贴到图片底边**，否则多行候选会掉到桌面上没有背景。
- **克隆皮肤时配置必须逐字一致**，只改六个身份字段。

详见 [docs/LESSONS.md](docs/LESSONS.md)。
